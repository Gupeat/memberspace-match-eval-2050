# 标签敏感度基线（#2050，交付 v3）

本文件回答一个具体问题：**+0.075025 的 v2−v1 NDCG@10 差值，是不是任何一组“看起来合理”的标签都会产生？**

结论先说：不是任何一组都会产生，但也不能反过来证明 v2 更好。与正式标签同底线（覆盖 ≥2）时，随机标签几乎都会让 v2 略高，实际标签位于第 41.0 百分位；降低到底线覆盖 ≥1 时，实际标签高于全部 500 个随机集；去掉底线后，v2 只在 247/500 个随机集中胜出，中位优势 -0.000253。因此 +0.075025 是夹具上的具体结果，不是泛化证据。

## 方法

脚本：`scripts/label_sensitivity.py`（只读、确定性、无第三方依赖）。

固定不动：

- 冻结的负例（2 rejected + 1 not_accepting + 有冲突时的 conflict）；
- 硬过滤规则；
- v1/v2 权重及排序逻辑；
- 60 条需求的 required capabilities、行业、区域、容量。

只替换：

- 每条需求的正例。对每个种子，用 `random.Random(seed).sample(pool[demand], len(actual_positives[demand]))` 抽取，保留该需求实际正例数；替换后重新计算 v1 与 v2 的逐需求 NDCG@10，再取平均，得到该种子的 v2−v1。

三个候选池：

1. **qualified**：覆盖 ≥2 个 required capabilities，且满足 active supply、非需求方、accepting、无冲突、不在 rejected 列表；与正式标签使用同一业务底线；
2. **covered**：覆盖 ≥1 个 required capabilities，其余硬过滤相同；
3. **eligible**：同样的硬过滤条件，但**去掉能力底线**。

统计：500 个种子（seed 0–499），输出 min、p05、median、p95、max、v2>v1 的种子数，以及实际标签差值在这 500 个差值中的百分位（小于等于实际值的比例）。结果同时写入 `artifacts/label-sensitivity.json`。

复现：

```bash
python scripts/label_sensitivity.py
python scripts/label_sensitivity.py --seeds 500 --json
```

输出是确定性的；同一解释器与同一数据下逐字节相同。

## 结果

实际标签：v1 NDCG@10=0.890098，v2=0.965123，v2−v1=**+0.075025**。

| 抽样池 | min | p05 | median | p95 | max | v2>v1 | 实际百分位 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| qualified（覆盖 ≥2） | +0.071324 | +0.073015 | +0.075438 | +0.079444 | +0.081850 | 500/500 | 41.0 |
| covered（覆盖 ≥1） | -0.009956 | +0.002333 | +0.023730 | +0.043425 | +0.058704 | 484/500 | 100.0 |
| eligible（无底线） | -0.031602 | -0.019889 | -0.000253 | +0.019415 | +0.032508 | 247/500 | 100.0 |

## 怎么读

1. **同底线时 v2 几乎总赢，但实际标签不在极端位置**：qualified 池 500/500 个随机标签集都给出正差值，中位 +0.075438；实际标签 +0.075025 位于第 41.0 百分位。原因是 v2 的能力权重更高（0.55 对 0.45），而 qualified 池要求覆盖至少两个能力；这不是标签偏向 v2 的证据，而是“底线 + 权重”共同产生的结构效应。
2. **降低底线会放大实际标签的差值**：covered 池（覆盖 ≥1）中位 +0.023730，实际标签差值高于全部 500 个随机集（百分位 100）。这说明“覆盖 ≥2”这条底线比“覆盖 ≥1”更强地筛选出 v2 偏好的候选，实际标签集不是随机的中性样本。
3. **去掉底线后优势消失**：eligible 池中 v2 只赢 247/500，中位 -0.000253，95% 区间跨 0（-0.019889 到 +0.019415）。这说明 +0.075025 不能脱离“业务底线”被解释成模型优势；若客户认为“应推荐”不应有覆盖 ≥2 的底线，本对比结论不成立。
4. **不能反推“标签独立”**：基线只检验“随机标签会怎样”，不检验标签是否与评分器共享业务事实。独立性的边界见 `docs/EVALUATION-LIMITS.md` 第 2 节；四特征网格最多只能覆盖 58/60 条需求，结构性失败为 d052 与 d036（后者 5 个正例，capability/region/company_id 的排序共同挤出 c024）。两条一起证明任何非负四特征权重都无法完整复现 top6 标签集合，因此不能声称与业务事实正交。

## 与 top6 的关系

190 个正例全部落在 v2 全量排名前 10 内（中位第 2，最差第 8）；v2 在 31 条需求上更好、28 条持平、1 条更差。v2 top6 精确等于标签集只在“该需求恰好 6 个正例”时有意义：本数据有 4 条，所以是 2/4；top6 覆盖全部标签 51/60，交集 180/190。随机化基线替换的是正例集合本身，因此它检验的是“标签集选择”，不是“v2 的 top6 排序是否完美”。

## 限制

- 这是 60 条合成需求上的枚举式基线，不是统计显著性检验；500 个种子足以展示分布形态，不构成置信区间。
- 随机抽样不模拟人类标注的语义判断；它只能回答“任意同规模标签会不会也这样”，不能回答“人类会怎么标”。
- 三个池都保留同一套硬过滤和负例；如果把负例也随机化，分布会变宽，未在本文件中报告。
- 结果依赖当前 fixture 与权重；改数据或改权重后必须重跑，不能引用本文件的数字。
